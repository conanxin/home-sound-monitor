# 架构说明

HomeSound 的核心链路很短：

```text
摄像头 RTSP 音频
  -> ffmpeg 解码成 mono PCM
  -> 每个摄像头写入独立环形缓冲区
  -> 浏览器连接时读取最新声音
  -> 多路声音混合
  -> ffmpeg 编码成 MP3
  -> HTTP 输出到浏览器
```

## 为什么只做声音

婴儿监听和房间监听最重要的是“是否有动静”。视频会带来更高带宽、更高功耗和更复杂的隐私风险。声音优先可以让手机长时间播放，也更容易后台使用。

## 为什么要有缓冲区

摄像头是持续输出的，浏览器用户可能随时打开页面。如果每次打开页面才连接摄像头，启动会慢，而且多个用户会重复拉流。

服务端持续读取摄像头声音，并只保留最近几秒。当浏览器连接时，服务端直接从最近的声音开始输出。

## 为什么实时优先

这个项目不是录音工具。用户最关心的是“现在房间有没有声音”，不是完整保存过去每一秒。因此当播放端落后太多时，应该跳过旧声音，回到接近实时的位置。

## 原型和生产版本的区别

当前 Python 原型便于理解和二次开发，但不是最终形态。更完整的版本可以继续加入：

- WebM/Opus 低延迟输出
- 音量限制器，避免多路混音爆音
- 每路单独音量和静音
- 摄像头断线状态
- 访问令牌
- Docker 和 systemd 部署
