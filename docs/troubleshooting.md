# 故障排查

这份文档按最常见的使用路径来排查：摄像头能不能读到音频、服务有没有启动、手机能不能访问、浏览器有没有播放。

## 1. 先检测摄像头

推荐先使用 HomeSound 内置检测命令：

```bash
python src/homesound.py probe "rtsp://user:password@192.168.1.31:554/stream1"
```

成功时会看到类似：

```text
视频轨道: 1
音频轨道: 1
  - aac 8000Hz 1ch
结论: 发现音频轨道，可以尝试接入 HomeSound。
```

如果显示没有音频轨道：

- 检查摄像头是否有麦克风。
- 检查摄像头后台是否开启音频。
- 尝试主码流和子码流的不同 RTSP 地址。
- 用摄像头厂商文档确认 RTSP 路径。

## 2. ffprobe 或 ffmpeg 找不到

如果看到：

```text
找不到 ffprobe。请确认 ffmpeg/ffprobe 已安装并在 PATH 中。
```

说明系统找不到媒体工具。需要安装 ffmpeg，并确认：

```bash
ffmpeg -version
ffprobe -version
```

两个命令都能运行。

## 3. 配置文件错误

启动时如果看到：

```text
配置文件有问题：
- cameras 中至少需要一个摄像头。
```

请检查 `config.yaml` 是否存在，以及 `cameras` 是否按照示例配置书写。

当前原型的 YAML 解析器比较简单，请注意：

- 使用空格缩进，不要使用 Tab。
- 不要写复杂嵌套结构。
- 每个摄像头至少要有 `name`、`url`、`volume`。
- `volume` 要写数字，例如 `1.0` 或 `0.8`。

## 4. 服务启动了，但手机打不开

确认手机访问的是服务器局域网 IP，而不是 `0.0.0.0`。

例如服务输出：

```text
HomeSound 已启动: http://0.0.0.0:8080
```

手机应该访问类似：

```text
http://192.168.1.20:8080
```

还需要检查：

- 手机和服务器是否在同一个 Wi-Fi / 局域网。
- 服务器防火墙是否允许 8080 端口。
- 端口是否被其他程序占用。

## 5. 网页打开了，但没有声音

先看状态接口：

```bash
curl http://127.0.0.1:8080/status
```

重点看每个摄像头：

- `online` 是否为 `true`。
- `last_audio_at` 是否有时间。
- `last_error` 是否有错误信息。
- `restarts` 是否一直增加。

如果 `online` 为 `false`，通常是摄像头地址、账号密码、网络或音频轨道有问题。

## 6. 日志里一直重试

类似日志：

```text
[儿童房 A] 音频读取失败，5 秒后重试: ...
```

排查顺序：

1. 用 `probe` 检测同一个 RTSP 地址。
2. 检查账号密码是否正确。
3. 检查密码里的特殊字符是否需要 URL 编码。
4. 检查摄像头是否限制同时观看人数。
5. 检查摄像头是否重启或离线。

## 7. 音量太大或爆音

多个摄像头混音时，声音会相加。如果两个房间同时很响，可能失真。

可以先把配置里的 `volume` 调低：

```yaml
cameras:
  - name: 儿童房 A
    volume: 0.7
  - name: 儿童房 B
    volume: 0.7
```

后续版本计划加入 limiter，自动降低爆音风险。

## 8. 延迟比较高

当前原型输出 MP3，兼容性好，但不是最低延迟方案。可以先尝试：

- 让手机和服务器在同一个稳定 Wi-Fi。
- 优先使用子码流或低带宽 RTSP 地址。
- 避免服务器负载过高。

后续版本计划增加 WebM/Opus 低延迟输出。

## 9. 不要公开真实地址

RTSP 地址里经常包含摄像头账号密码。HomeSound 会在日志和 `/status` 中脱敏 URL，但你仍然不应该公开：

- 真实 `config.yaml`。
- 摄像头 IP、账号、密码。
- 家庭网络截图。
- 完整日志。
